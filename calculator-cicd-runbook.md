# Calculator CI/CD Assignment: Runbook

**Stack:** GitHub Actions • Docker • AWS OIDC • AWS SAM • S3 • CloudFormation • Lambda

## 1. Overview

A small Python calculator (add, subtract, multiply of two positive integers) is tested inside Docker and then deployed to AWS Lambda using AWS SAM. GitHub Actions runs everything on every push.

- **CI:** build the Docker image and run the unit tests inside it.
- **CD:** if tests pass on a push to `main`, deploy to AWS Lambda with SAM.

## 2. Architecture

```
Developer --git push--> GitHub Repo
                           |
                  GitHub Actions (ci-cd.yml)
                           |
        +------------------+--------------------+
        |                                       |
   test job                               deploy job (needs: test, main only)
   1. docker build                        1. OIDC login to AWS (temporary credentials)
   2. docker run (unit tests)             2. sam validate + sam build
                                          3. sam deploy
                                                |
                          S3 (SAM artifact bucket) --> CloudFormation stack --> Lambda
```

## 4. Steps

### Step 1: Create the repo
Create a GitHub repository, clone it, and create the folders shown above.

### Step 2: Write the calculator

`calculator/app.py`
```python
def _check(a, b):
    for n in (a, b):
        if isinstance(n, bool) or not isinstance(n, int) or n <= 0:
            raise ValueError("Inputs must be positive integers")


def add(a, b):
    _check(a, b)
    return a + b


def subtract(a, b):
    _check(a, b)
    return a - b


def multiply(a, b):
    _check(a, b)
    return a * b
```

### Step 3: Write unit tests (unittest)

`calculator/tests/test_calculator.py`
```python
import unittest
from app import add, subtract, multiply


class TestCalculator(unittest.TestCase):
    def test_add(self):
        self.assertEqual(add(2, 3), 5)

    def test_subtract(self):
        self.assertEqual(subtract(5, 3), 2)

    def test_multiply(self):
        self.assertEqual(multiply(4, 3), 12)

    def test_rejects_zero(self):
        with self.assertRaises(ValueError):
            add(0, 5)

    def test_rejects_negative(self):
        with self.assertRaises(ValueError):
            multiply(-1, 5)

    def test_rejects_non_integer(self):
        with self.assertRaises(ValueError):
            subtract(2.5, 1)


if __name__ == "__main__":
    unittest.main()
```

Run locally from the `calculator` folder:
```
python -m unittest discover -s tests -v
```

### Step 4: Write the Lambda handler

`calculator/lambda_function.py`
```python
from app import add, subtract, multiply

OPERATIONS = {"add": add, "subtract": subtract, "multiply": multiply}


def lambda_handler(event, context):
    try:
        result = OPERATIONS[event["operation"]](event["a"], event["b"])
        return {"statusCode": 200, "result": result}
    except (KeyError, ValueError) as e:
        return {"statusCode": 400, "error": str(e)}
```

`calculator/test-event.json`
```json
{ "operation": "add", "a": 10, "b": 5 }
```

`calculator/requirements.txt` is empty (no external libraries are needed).

### Step 5: Containerize with Docker

`calculator/Dockerfile`
```dockerfile
FROM python:3.12-slim
WORKDIR /app/calculator
COPY calculator/ /app/calculator/
CMD ["python", "-m", "unittest", "discover", "-s", "tests", "-v"]
```

Test locally from the repo root:
```
docker build -f calculator/Dockerfile -t calculator-cicd:latest .
docker run --rm calculator-cicd:latest
```

### Step 6: Write the SAM template

`calculator/template.yaml`
```yaml
AWSTemplateFormatVersion: '2010-09-09'
Transform: AWS::Serverless-2016-10-31
Description: Calculator Lambda function

Resources:
  CalculatorFunction:
    Type: AWS::Serverless::Function
    Properties:
      FunctionName: calculator-cicd
      CodeUri: .
      Handler: lambda_function.lambda_handler
      Runtime: python3.12
      MemorySize: 128
      Timeout: 10
      Role: arn:aws:iam::<ACCOUNT_ID>:role/CalculatorLambdaExecutionRole
```

Replace `<ACCOUNT_ID>` with your AWS account ID.

Test locally from the repo root:
```
sam validate --template-file calculator/template.yaml
sam build --template-file calculator/template.yaml
sam local invoke CalculatorFunction --event calculator/test-event.json
```

### Step 7: Create the Lambda execution role (AWS Console)
1. Go to **IAM → Roles → Create role** → trusted entity **AWS service → Lambda**.
2. Attach **AWSLambdaBasicExecutionRole** (basic CloudWatch logging).
3. Name it `CalculatorLambdaExecutionRole`.

### Step 8: Set up GitHub to AWS login with OIDC (AWS Console)
This avoids storing long-lived AWS access keys in GitHub.

1. Go to **IAM → Identity providers → Add provider**.
   - Type: **OpenID Connect**
   - Provider URL: `https://token.actions.githubusercontent.com`
   - Audience: `sts.amazonaws.com`
2. Go to **IAM → Roles → Create role** → **Web identity** → select the provider above.
3. Name it `GitHubActionsCalculatorDeployRole`.
4. Edit its **trust policy** so only your repo's `main` branch can assume it:

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": { "Federated": "arn:aws:iam::<ACCOUNT_ID>:oidc-provider/token.actions.githubusercontent.com" },
    "Action": "sts:AssumeRoleWithWebIdentity",
    "Condition": {
      "StringEquals": { "token.actions.githubusercontent.com:aud": "sts.amazonaws.com" },
      "StringLike":   { "token.actions.githubusercontent.com:sub": "repo:<OWNER>/<REPO>:ref:refs/heads/main" }
    }
  }]
}
```

> If your GitHub repo uses the newer immutable subject format (check **Settings → Actions → OIDC**), use that exact `sub` value instead.

### Step 9: Give the deploy role permissions
Create a policy named `CalculatorCICDDeploymentPolicy` and attach it to `GitHubActionsCalculatorDeployRole`. It must allow:

- Upload and read artifacts in the existing SAM S3 bucket (`aws-sam-cli-managed-default-samclisourcebucket-zpdfvgbvhodq`).
- Create and manage the `calculator-cicd` CloudFormation stack and change sets, including `CreateChangeSet` on the SAM transform `arn:aws:cloudformation:ap-south-1:aws:transform/Serverless-2016-10-31`.
- Manage the `calculator-cicd` Lambda function.
- `iam:PassRole` for `CalculatorLambdaExecutionRole` only.

Keep permissions as narrow as practical. Add an action only when a deployment error names it.

### Step 10: Add GitHub repository variables
In the repo go to **Settings → Secrets and variables → Actions → Variables** and add:

| Variable | Value |
|---|---|
| `AWS_ROLE_ARN` | ARN of `GitHubActionsCalculatorDeployRole` |
| `AWS_REGION` | `ap-south-1` |

### Step 11: Create the GitHub Actions workflow

`.github/workflows/ci-cd.yml`
```yaml
name: CI-CD Pipeline

on:
  push:
    branches: [ main, "feature/**" ]
  pull_request:
    branches: [ main ]

permissions:
  id-token: write
  contents: read

jobs:
  test:
    name: Build Docker image and run tests
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build Docker image
        run: docker build -f calculator/Dockerfile -t calculator-cicd:latest .
      - name: Run unit tests in container
        run: docker run --rm calculator-cicd:latest

  deploy:
    name: Deploy to AWS Lambda
    needs: test
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ vars.AWS_ROLE_ARN }}
          aws-region: ${{ vars.AWS_REGION }}
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - uses: aws-actions/setup-sam@v2
      - name: Validate SAM template
        run: sam validate --template-file calculator/template.yaml
      - name: Build
        run: sam build --template-file calculator/template.yaml
      - name: Deploy
        run: >
          sam deploy
          --template-file .aws-sam/build/template.yaml
          --stack-name calculator-cicd
          --s3-bucket aws-sam-cli-managed-default-samclisourcebucket-zpdfvgbvhodq
          --region "$AWS_REGION"
          --no-confirm-changeset
          --no-fail-on-empty-changeset
        env:
          AWS_REGION: ${{ vars.AWS_REGION }}
```

Key points:
- The `deploy` job has `needs: test`, so a failed test blocks deployment.
- Deployment runs only on a push to `main`; pull requests and feature branches only run tests.
- `--no-confirm-changeset` lets the pipeline continue without a prompt.
- `--no-fail-on-empty-changeset` treats "nothing changed" as success.

### Step 14: Verify the deployment
1. **GitHub → Actions:** open the latest run and confirm the `test` and `Deploy to AWS Lambda` jobs are green.
2. **AWS Lambda (ap-south-1):** confirm `calculator-cicd` exists with current code.
3. **CloudFormation:** open stack `calculator-cicd` and check its status and events.
4. **S3:** check the SAM bucket for the uploaded package. Do not delete the bucket or its objects.
5. **Test the function:** in the Lambda console, use the **Test** tab with this event:

```json
{ "operation": "multiply", "a": 4, "b": 3 }
```
Expected result: `{"statusCode": 200, "result": 12}`

## 5. Problems Encountered and Fixes

| Problem | Cause | Fix |
|---|---|---|
| OIDC role assumption failed | Trust policy used the older repo subject format | Updated the trust policy to the exact repo and `main` subject GitHub showed |
| S3 `PutObject` AccessDenied | Deploy role had no effective permission to upload artifacts | Checked bucket permissions and updated the role policy |
| CloudFormation `CreateChangeSet` AccessDenied | Policy did not allow the SAM transform | Added the SAM transform ARN to the CloudFormation resource scope |

## 6. Demo Flow (Commit to AWS)

1. Make a small change in `calculator/app.py` or the tests.
2. Commit and push to `main`.
3. Show the **Actions** tab: the test job runs in Docker, then the deploy job runs.
4. Show the `calculator-cicd` stack in CloudFormation and the function in Lambda.
5. Run the Lambda test event to show it working.
6. (Optional) Break a test and push to a feature branch. Show that tests fail and nothing is deployed.

## 7. Cost Safety

Lambda invocations, logs, and storage can incur charges. Before finishing, review billing. If you delete the `calculator-cicd` stack, it removes the resources it manages, so inspect it first.
